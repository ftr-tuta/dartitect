(`0ad88ea1b3402cf60f1184a364e8d8d8dff4a012`, `1.0.0-rc.1`) is not the active

`eb2693fa92ccf30546568ade6133c253776d5cab`, version `1.0.0-rc.2`, on branch

The allowed states are `UNREPRODUCED`, `RED`, `FIXED`, `REJECTED`, and
`DEFERRED`. An existing implementation, test, or release note is context only:
it does not move a finding from `UNREPRODUCED` until the finding's exact minimal
reproduction has been executed.

== Findings

[cols="1,1,2,4"]
|===
|ID |State |Goal |Baseline note and next evidence

|`DRT-P0-001`
|`FIXED`
|02
|RED: the minimal old-cleanup failure published generation 2 and its new root,
but the caller received only a generic `ResourceCleanupException`, with no way
to distinguish post-publication cleanup from failed publication. FIXED:
`OwnedRuntimeReplacementCleanupException` now carries
`publishedGeneration == 2`, the original cleanup error/stack, and preserves the
new authoritative root. Focused lifecycle tests pass.

|`DRT-P0-002`
|`FIXED`
|02
|RED: disposing from `onChanged` during the first unkeyed and keyed transition
raised `LateInitializationError: Field 'work' has not been initialized` while
draining the newly visible entry. FIXED: each entry publishes an initialized
completion latch before the callback and attaches the action afterward. The
full cancel/dispose reentrancy matrix passes for reject, join, drop, sequential,
restart-latest, concurrent, and keyed policies with zero residual work.

|`DRT-P0-003`
|`FIXED`
|03
|RED: a computed-originated `update` returned normally, published an implicit
nested flush, and failed the expected rejection; the pending graph was exposed
to two logical commits. FIXED: `ReactiveOwnerPhase` rejects writes during
compute/commit, custom equality runs under compute, failed compute preserves the
snapshot/revision, and pre-commit dispose is rejected. Notify reentrancy remains
explicitly deferred.

|`DRT-P0-004`
|`FIXED`
|03
|RED: the value and revision committed, then `StateError: listener failed` was
rethrown from `notifyListenersSafely` to the mutation caller. FIXED: every
listener failure is reported after commit, other listeners continue, reporter
failure is isolated, and `update` returns its successful body outcome without
encouraging retry.

|`DRT-P1-001`
|`FIXED`
|03
|RED: re-registering the same type/name/dependencies returned the old node but
kept its obsolete compute closure (`expected 6`, `actual 4`). FIXED:
`ReactiveKey` identity is owner-local type/namespace/name with required positive
definition revision and non-empty fingerprint. Compatible registration refreshes
the closure; mismatches report both definitions. `ViewModelHost.onReassemble`
preserves compatible state and reports incompatible definitions through
`FlutterError`; hot restart remains a new owner/graph.

|`DRT-P0-005`
|`FIXED`
|04
|RED: with the supervisor event loop blocked across deadline/result ordering,
public ID `reused` was admitted again and the new request returned the old
payload (`expected 2`, `actual 1`). An early unsendable-payload failure also
left the unawaited ACK Future error in the zone. FIXED: protocol v2 uses a
monotonic generation-local internal nonce on the wire, discards stale nonces,
and installs internal observation branches for ACK/result while preserving
their caller-visible errors.

|`DRT-P0-006`
|`FIXED`
|04
|RED: an effect queued before mount produced timeline
`effect:false:9, frame`, proving synchronous `initState` delivery before the
first post-frame context. FIXED: Flutter attachment is post-frame; delivery
waits while `TickerMode` is disabled or the route is non-current, resumes once
for the same binding, and is released by detach/swap/channel disposal. Headless
channel policy remains independent and immediate.

|`DRT-P0-007`
|`FIXED`
|05
|RED: a dataset handler advanced past lease expiry and still performed its
consumer-owned write (`datasetApplied == true`). FIXED: each handler receives a
run-bound `SyncAuthority`; the engine checks it before and after application,
and the consumer contract requires the fencing token to be compared atomically
inside the dataset transaction. Tests reject stale token 7 against store token
8 and prevent application after expiry.

|`DRT-P0-008`
|`FIXED`
|05
|RED: journal and lease-release faults after successful application/checkpoint
escaped as raw `StateError`s without a durable terminal account. FIXED:
application, checkpoint, journal, lease release, and optional consumer cleanup
produce independent receipts. Unexpected terminal failures throw
`SyncRunTerminalException` only after release, cleanup, and progress close,
carrying the complete report and original cause/stack.

|`DRT-P0-009`
|`FIXED`
|06
|RED: the reviewed baseline token was only eight hex digits (`96e1523b`), a
128 KiB unrelated asset caused `stale_plan`, and concurrent callers produced
zero receipts through filesystem races. FIXED: schema-v1 semantic manifests use
SHA-256; one service-owned OS lock spans revalidation through journal cleanup;
real processes produce exactly one commit; abrupt holder death releases the
lock; relevant Dart inputs still invalidate the plan.

|`DRT-P0-010`
|`FIXED`
|06
|RED: standard Freezed/header and configured-suffix files were not generated;
the live plugin reported local `Store`, local `getIt`, and an ordinary
configuration map as provider/locator/sensitive telemetry violations. FIXED:
resolved library identity, telemetry-sink context, header+suffix policy, and an
explicit invalid-config diagnostic feed one five-case scanner/plugin corpus.
Budgets passed at 177 ms scanner and 3413 ms analyzer.
