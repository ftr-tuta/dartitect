= Getting started

Start with a new Dartitect project. There is no conversion, gradual adoption,
legacy zone, or competing-runtime mode. Keep domain contracts free of
Dartitect types when ordinary Dart types suffice.

[source,dart]
----
final class AppRuntime implements AsyncDisposable {
  AppRuntime(this.repository, this._owner);

  final OrdersRepository repository;
  final ResourceOwner _owner;

  static AppRuntime create() {
    final owner = ResourceOwner(label: 'AppRuntime');
    try {
      final client = owner.own(createClient(), (value) => value.close());
      return AppRuntime(HttpOrdersRepository(client), owner);
    } catch (_) {
      unawaited(owner.disposeAsync());
      rethrow;
    }
  }

  @override
  Future<void> disposeAsync() => _owner.disposeAsync();
}
----

At a route boundary, use `ViewModelHost.create` for an owned ViewModel and
`.value` for a borrowed one. The host does not listen to the ViewModel; place a
`ListenableBuilder`, `ValueListenableBuilder`, or `ListenableSelector` at the
smallest rebuilding fragment.

Create only the requested platforms, review config v2, and preview every
generated change:

[source,shell]
----
dart run dartitect_cli:dartitect create app orders_app --targets=android,web
cd orders_app
dart run dartitect_cli:dartitect scan --json
dart run dartitect_cli:dartitect doctor
dart run dartitect_cli:dartitect create feature orders \
  --profile=local --scope=application --targets=android,web --dry-run
----

Generated-once files belong to the consumer immediately. A conflicting file is
never overwritten and there is no `--force` flag.
