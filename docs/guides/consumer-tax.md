# Consumer-tax ratchets

`dartitect inspect --consumer-tax --json` is a read-only gate for projects
created with Dartitect. It measures consumer-owned source rather than generated
outputs and returns exit code 1 when a structural or profile budget ratchet is
exceeded.

The report records manual plumbing, listeners, lifecycle/disposal calls,
cancellation sources, provider-specific wiring, referenced symbols,
generated-once structural files, unused direct dependencies, source size,
generated bytes, and dependency count. CI may provide actual analyzer and build
timings in `.dartitect/consumer-tax-metrics.json` schema 1:

```json
{
  "schemaVersion": 1,
  "analysisMillis": 4200,
  "buildMillis": 38000
}
```

Timing evidence is observed but never synthesized by the read-only command.
The generated-project matrix records it around the real analyzer and build/test
processes before invoking the gate.

Ratchets are selected by the most capable declared feature profile: `local`,
`online`, `cache`, `replica`, or `offline-full`. Every profile permits zero
manual assembly plumbing and zero purely structural generated-once files.
Concrete provider owners, SDK engine construction, nullable `Object?`
capability slots, and `null` capability slots fail regardless of profile.

Config v2 is the opt-in authority for dependency closure. An empty/local shell
cannot resolve Dio, Drift, sync, or Workmanager packages. Transport, storage,
dataset sync, and scheduler dependencies become eligible only when the matching
typed config block selects them. Direct Dartitect runtime dependencies unused
by any `lib/` import also fail.

Generated `*.dartitect.g.dart` files are measured for size and dependency use,
but generated plumbing does not count as consumer-authored tax. Tests are also
excluded from runtime consumer-tax counts.
