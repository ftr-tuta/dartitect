== Technical authority

GitHub Actions owns all tests, security checks, native evidence, clean-clone
audits, benchmarks, and Git-without-overrides canaries. The coordinated `CI`
workflow runs on pull requests, merge queue candidates, and pushes to `main`.
The `Security` workflow is diagnostic-only; merge-candidate OSV scanning runs
inside `CI` and therefore contributes to the single required result.

`CI / Required` depends on every Linux, Windows, macOS/iOS, Android emulator,
Drift Web/Chrome, clean-clone, Git-consumption, and OSV job. A failure, cancellation, or skipped
dependency makes the aggregate check fail.

The Linux floor cell also reproduces the 12-scenario change-tax study on one
pinned runner. Each scenario must keep semantic architecture plumbing at zero
while recording manual/generated diffs and real generation, analyzer, and build
durations.

== Main readiness artifact

Only a successful `push` run on `main` creates `actions-readiness-v1`. The
artifact contains the exact source SHA and Git tree, workflow run ID and
attempt, all eight required job conclusions, the five native manifests, and
SHA-256 digests for every included policy and deterministic Release input.
Pull requests validate the implementation but do not create release
authorization.

`dart run tool/check_actions_readiness.dart --contract-only` validates structure and
explicitly cannot declare readiness. Formal mode runs only inside the hosted
main CI execution and accepts only the artifact from that current run. Missing,
expired, cross-run, cross-SHA, cross-tree, skipped, cancelled, or altered input
fails closed.

== Native matrix

The nominal matrix is identical for RC and stable validation:

* Android API 24 build compatibility;
* Android API 34 runtime on a clean GitHub-hosted Google APIs x86_64 AVD;
* iOS 14 media build;
* iOS 12 privacy build;
* current iOS runtime on an installed `macos-15` simulator.

No technical evidence uses consumer hardware or a privately managed runner.
Local runs are optional development feedback only.

== Stable UI-quality evidence

Version 1.0.0 includes the business-neutral responsive entrypoint, exhaustive borrowed
builders, and the dev-only paired UI matrix without owning product controls,
themes, strings, locales, navigation, or visual identity. The machine-readable
`ui-quality-v1` contract verifies API and inventory freshness, CLI/analyzer
diagnostic parity, the managed skill, generated scaffold, accessibility canary,
shared-layout goldens, and all six hosted platform build definitions. Stable
promotion accepts an empty blocker list only while that evidence passes.

== Drift storage matrix

Linux, Windows, and macOS run the real consumer-generated native fixture with
`NativeDatabase.createInBackground`, migration/reopen, CRUD, transactions, and
watch behavior. Linux additionally opens generated ObjectBox and Drift stores
simultaneously in distinct bounded contexts.

The hosted `drift-web` job compiles the consumer worker, verifies the pinned
Drift 2.34.3 `sqlite3.wasm` digest and MIME, then drives two same-origin pages
through Chrome DevTools Protocol. Portable and COOP/COEP-isolated profiles must
both prove migration, CRUD, commit/rollback, watch propagation, persistence,
safe multi-context storage, and foreground resume. There is no in-memory,
unsafe IndexedDB, missing-Chrome, or WebDriver fallback.

== Recorded release

The manual `Release` workflow was the human decision point. Its actor supplied
only `source_sha` and `ci_run_id`. Before any write, the workflow proved that
the SHA was the current remote `main` HEAD, the CI push run and
`CI / Required` succeeded for it, and the unexpired readiness artifact matched
the run attempt, source tree, eight jobs, and all hashes. It then created the
annotated `v1.0.0` tag and immutable stable/latest GitHub Release using the
idempotent transaction recorded in the release runbook. The actor is
provenance, not technical evidence; there is no Dartitect registry channel.
