= RC and stable validation in GitHub Actions

Status:: ACTIONS POLICY READY
Goal:: V1S-17
Machine contract:: `tool/rc_validation_contract.json`

RC and stable candidates use the same nominal five native cells recorded in
`actions-readiness-v1`: Android API 24 build, Android API 34 hosted emulator,
iOS 14 media build, iOS 12 privacy build, and the current hosted iOS simulator.
There is no separate nine-cell matrix or device receipt set.

The coordinated CI graph runs minimal, offline-first, native-capability, Git
consumption, clean-clone, benchmark, release-audit, and native scenarios before
`CI / Required` succeeds. Native runtime canaries execute on the hosted Android
AVD and iOS simulator; absence or boot failure fails the aggregate check.

`dart run tool/check_rc_validation.dart --contract-only` verifies the immutable
policy locally without claiming readiness. Formal RC/stable validation consumes
only the main run's `actions-readiness-v1` manifest and its hashed artifacts.
No local file, manual receipt, mutable decision record, consumer device, or
privately managed infrastructure can complete the gate.
