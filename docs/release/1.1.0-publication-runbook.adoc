== Operator preflight

Immediately before dispatch, an authenticated repository administrator must
verify all of the following without changing repository state:

* `GET /repos/ftr-tuta/dartitect/immutable-releases` reports `enabled: true`;
* ruleset `21525640` is active, targets tags, includes only `refs/tags/v*`,
  protects deletion and non-fast-forward updates, and has no bypass actors;
* the remote `main` HEAD is the intended stable `1.1.0` source;
* the successful `CI` push run for that exact SHA contains one successful
  `CI / Required` job and an unexpired `actions-readiness-v1` artifact;
* the diagnostic `Security` workflow has succeeded for the same `main` source;
* neither the Git tag nor a GitHub Release named `v1.1.0` exists.

Any ambiguity stops the procedure. A green pull request, local validation, or
candidate run is not publication authority.

== Annotated tag and immutable Release

The workflow creates an annotated Git tag object through the GitHub API, then
creates `refs/tags/v1.1.0` and verifies that the peeled commit equals
`source_sha`. It creates the exact draft Release with `--verify-tag`, uploads
and verifies the deterministic asset set, and publishes it as stable and
latest. Final checks require `immutable: true` and successful GitHub Release
and asset attestations.

The transaction is idempotent only in these exact states:

* an existing matching annotated tag continues;
* an existing matching draft may replace only its expected draft assets;
* an already published Release succeeds only after exact identity,
  immutability, asset, checksum, and attestation verification;
* every divergent tag, Release, body, title, target, or asset fails without
  deletion, movement, or overwrite.

After publication, any correction requires `v1.1.1`. The immutable `v1.1.0`
Release is never edited or recreated.
