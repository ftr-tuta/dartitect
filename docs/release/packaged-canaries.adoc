= Packaged and Git candidate canary contract

Status:: Implemented for the RC6 candidate; final tag/publication are outside this delivery
Machine authority:: `tool/canaries/canary_contract.json`
Development gate:: `dart run tool/check_canaries.dart --allow-dirty`

== Candidate source and isolation

The packaged gate creates archives for all twenty-four packages from one exact
candidate tree, serves them through an ephemeral hosted repository, and copies
each consumer outside the checkout. It rejects local path resolution,
dependency overrides, missing/transitive cohort members, mixed versions,
archive digest mismatch, symlinks, and workspace-root leakage. A shared pub
cache is only transport; each requested archive digest remains authoritative.

The Git variant requires one annotated tag and resolves the complete transitive
Dartitect closure from one URL/ref. It remains release infrastructure, but this
RC6 delivery creates no tag, GitHub Release, or publication. Both runners use
the same six-canary machine contract and command order.

== Modeling and thin consumer

The pure-Dart modeling canary is
+examples/model_generator_fixture+. It installs only core/modeling/compiler/CLI,
applies committed generation in the isolated copy, checks freshness, executes
+dartitect verify+, analyzes, and tests equality, JSON, projection, and mapper
on VM and Chrome. This is also the clean-clone and Web modeling evidence.

The +thin_consumer_canary+ is generated from the +offline-hybrid+ preset with
all opt-in capabilities. It runs strict config and wiring freshness checks,
analyzes, tests, and builds Web. Its consumer-owned Dart files must contain no
manual bootstrap coordinator, provider owner, sync engine, mutation command,
job dispatcher, or diagnostics wiring.

== Flutter, providers, and workspace

The minimal canary covers generated consumer ownership, Flutter MVVM,
non-cooperative cancellation, large assets, and a multipackage workspace. The
offline-first canary covers ObjectBox native, separate ObjectBox/Drift bounded
contexts, outbox sync, session replacement, and host desktop build. The Drift
provider canary owns its schema/generator and forbids ObjectBox. The native
capabilities canary covers privacy, media, locale BR, and geometry without
storage providers.

The dedicated +examples/paved_road_canary+ exercises all four feature profiles,
application/session hosts, typed progress, lazy computed values, restoration,
history, resilience, jobs, transfer, and diagnostics. Its release Web build
must not contain the development service-extension namespace.

ObjectBox primary-constructor evidence is intentionally two-part: the exact
5.3.2 primary +var+ candidate must fail under its pinned Analyzer 10.2 resolver,
and the narrowly excepted traditional entity must generate and pass a real
native Store test. The mixed Dartitect+ObjectBox+Drift evidence keeps generator
contexts and data writers in separate bounded packages; it proves coexistence,
not a same-package resolver, bridge, dual-write, or cross-engine transaction.

== Receipts and release rule

Receipts record source SHA, package/archive digests, resolved graph, commands,
platform, duration, and zero residual-resource census. Development receipts may
identify a working tree and cannot become release authority. Final evidence
must be rerun from the exact committed candidate; a partial pass, dirty tree,
stale catalog, or differently resolved cohort is rejected.
