This procedure records the completed `1.0.0` publication. It is not a template
for a later patch and must not be dispatched again. A future version requires
explicit authorization, new version-specific evidence, and a new runbook.

== Recorded authorization

After the release PR was squash-merged, the operator waited for the successful
`CI` push run on the new remote `main` HEAD and started `Release` with exactly:

* `source_sha`: the full lowercase SHA at remote `main` HEAD;
* `ci_run_id`: the successful `CI` run that produced
  `actions-readiness-v1` for that SHA.

There is no channel selector, registry token, PAT, GitHub App, or environment
secret. `Release` is the only workflow with `contents: write`.

=== Recorded administrative operator preflight

Immediately before the one authorized dispatch, an administrator verified
through an authenticated local `gh` session that:

* `GET /repos/ftr-tuta/dartitect/immutable-releases` returns `enabled: true`;
* ruleset `21525640` is active, targets tags, includes only `refs/tags/v*`, has
  deletion and non-fast-forward protection, and has an empty `bypass_actors`;
* tag and Release `v1.0.0` are absent, or are the exact retry state described
  below.

These checks use the operator's existing repository administration authority;
its credential is never passed to Actions. GitHub's workflow `GITHUB_TOKEN`
cannot be granted Repository Administration permission, which the immutable
Release settings endpoint requires. The workflow therefore revalidates the
public portion of the tag ruleset before writing and proves `immutable: true`
plus the Release attestation immediately after publication.

== Recorded read-only preflight

Before any repository write the workflow proved all of the following:

. `source_sha` equals the current remote `main` HEAD;
. the public view of ruleset `21525640` has the required name, target,
  enforcement, ref conditions, deletion rule, and non-fast-forward rule;
. `ci_run_id` is a successful `CI` push run for that exact SHA and has one
  successful `CI / Required` job;
. the unexpired `actions-readiness-v1` manifest matches the SHA, source tree,
  run ID, run attempt, eight required jobs, and every copied artifact hash;
. the stable-candidate, package-release, and distribution-policy gates pass;
. `v1.0.0` and Release `v1.0.0` are absent, or their existing state exactly
  matches the authorized source and immutable asset contract.

Any ambiguity or divergence observable by the operator or workflow fails closed
before a write.

== Recorded deterministic assets

The workflow generated and uploaded:

* `actions-readiness-v1.json`;
* `release-provenance.json`;
* `dartitect-git-manifest.json`;
* `dependency-snippets.zip`, with one descriptor per package and core,
  Flutter, Drift, ObjectBox, and tooling profiles;
* `sbom.spdx.json`;
* `dependency-licenses.json`;
* `SHA256SUMS`.

`SHA256SUMS` covers every other uploaded asset. The workflow uploads to a draft,
downloads all assets again, validates names and SHA-256 digests, and publishes
only after the round trip succeeds.

== Executed tag and Release transaction

The workflow created an annotated Git tag object through the GitHub API, then
created `refs/tags/v1.0.0`, and verified that the peeled ref equaled
`source_sha`. It created the draft with `gh release create --verify-tag`,
uploaded the assets, verified them after download, and then published the
Release as stable and latest.

The executed transaction defined these idempotency rules:

* an exact existing annotated tag continues;
* an exact existing draft may replace only its draft assets before revalidation;
* an already published Release succeeds only after exact identity, immutability,
  asset, checksum, and attestation verification;
* every divergent tag, Release, or asset fails without deletion, movement, or
  overwrite.

After publication, any correction requires `v1.0.1`. The immutable `v1.0.0`
Release is never edited or recreated.
