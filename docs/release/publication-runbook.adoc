= Lockstep 1.0 publication runbook

Status:: Manual trigger; technical evidence fully automated
Machine authority:: `tool/actions_readiness_policy.json`
Workflow:: `.github/workflows/publish.yaml`

== Inputs

The actor starts `Publish` with exactly:

* `source_sha`: full lowercase SHA already contained in `main`;
* `ci_run_id`: successful `CI` push run for that SHA;
* `channel`: `github-release`, `pub-dev-prerelease`, or `pub-dev-stable`.

This choice is the only human release decision. It supplies no missing test,
security, native, canary, benchmark, or audit evidence.

== Fail-closed verification

Before any external write, the workflow:

. validates input shapes and checks out `source_sha` exactly;
. queries the GitHub Actions API and requires a successful `CI` push on `main`
  whose head SHA is `source_sha`;
. downloads `actions-readiness-v1` from `ci_run_id` (an expired artifact fails);
. requires `CI / Required`, the matching SHA/tree/run ID and attempt, and
  successful conclusions for every coordinated job;
. recomputes every native and repository artifact SHA-256;
. validates that prerelease/stable channel selection matches the cohort;
. records `GITHUB_ACTOR`, source SHA, CI run, channel, and publication run URL.

Any missing, skipped, cancelled, failed, expired, cross-run, cross-SHA,
cross-tree, or altered input stops before tag, Release, or package publication.

== Publication order

pub.dev uses the exact `publicationOrder` in
`tool/package_release_contract.json`:

[source,text]
----
dartitect
dartitect_cli
dartitect_geometry
dartitect_lints
dartitect_locale_br
dartitect_privacy
dartitect_flutter
dartitect_isolates
dartitect_mcp
dartitect_media
dartitect_observability
dartitect_sync
dartitect_dio
dartitect_objectbox
dartitect_sentry
dartitect_testing
----

The workflow stops on the first publication failure. pub.dev versions are
immutable, so a partial cohort is never overwritten or completed from another
source SHA; prepare a new version after diagnosing the failure.

== Channels

`github-release` creates the version tag/Release at `source_sha` and attaches
publication provenance plus the readiness manifest. A pub.dev channel creates
the exact version tag, configures the repository secret token, and publishes
the cohort sequentially. The GitHub run itself remains the durable actor and
operation record.

No phone, tablet, iPhone, USB device, or private runner participates in this
workflow. Local dry-runs are useful feedback but never publication authority.
