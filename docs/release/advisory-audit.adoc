= Dependency advisory audit

Status:: LOCAL POLICY GREEN; `CI / Required` RESULT PENDING
Snapshot:: 2026-08-27

The coordinated `CI` workflow pins the official OSV-Scanner 2.5.1 direct action
at reviewed commit `ffa0a5f39214d80778c9b494822d94d0d9668458`. Its read-only
merge-candidate job runs for pull requests, merge queues, and `main` pushes and
is a dependency of `CI / Required`. The separate `Security` workflow is only a
manual/weekly diagnostic SARIF upload. Both paths scan recursively, fail on a
vulnerability, and pass the root `osv-scanner.toml`, covering all Pub lockfiles.

Pull-request, merge-queue, and root/main scans use the direct official action
with read-only permissions and do not generate or upload SARIF. This is
necessary because the upstream reusable workflow unconditionally requests
`security-events: write` even when its `upload-sarif` input is false, and GitHub
correctly rejects an attempted permission elevation from a read-only caller.
Manual and scheduled diagnostic scans use the reusable workflow and receive
only the additional `security-events: write` permission needed to upload SARIF
to Code Scanning. Neither workflow uses
`pull_request_target` or a differential PR scan.

The release audit rejects external Actions that are not pinned to full reviewed
commit SHAs. It also rejects OSV `PackageOverrides`, package-wide ignore
switches, and vulnerability exceptions without an exact ID, a substantive
justification, an HTTPS analysis link, and a non-expired `ignoreUntil` date no
more than 30 days away. There are currently no exceptions.

The local configuration and policy validator pass. Formal readiness is recorded
only when the successful main `CI / Required` run and its
`actions-readiness-v1` artifact exist; diagnostic SARIF is not a branch or
release gate.
